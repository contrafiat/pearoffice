# Slides

**Status:** approved by Tim 2026-10-06. Parity check: `notes/2026-10-06-impress-parity.md`.

**Goal:** PearOffice can make, share, co-edit and present slide decks, using
the same sharing, roles, seeders, moves, deleting and pictures as sheets
and documents.

**Tier:** T2. A new file kind (`slides`) in invite links and the file list,
a new shape inside the Yjs doc and new presence fields. Pictures reuse the
picture cores from `proposals/2026-10-06-document-images.md` unchanged. No
change to signing, membership, the join handshake or the seeder.

## What Slides v1 is

- A slide list: add, duplicate, delete and reorder (drag or keys)
- Layouts: title, title and content, two columns, section header, title
  only, blank. A layout only places text boxes; changing it moves the
  boxes and keeps their text
- Text boxes with the document editor's text features: bold, italic,
  underline, strikethrough, colour, highlight, font, size, alignment, line
  spacing, lists, links, superscript and subscript
- Shapes (rectangle, rounded rectangle, ellipse, triangle, arrow, line)
  with fill, outline and text inside; pictures, as in documents
- Move, resize and rotate with handles and arrow keys; snapping to the
  slide's edges and centre and to other objects, with guide lines; bring
  forward and send back
- A few fixed themes (fonts, background, text and accent colours); speaker
  notes under each slide
- Present full screen: arrows, space, Page Up and Page Down (clickers),
  click, Home, End, B and W (black or white screen), Esc. On desktop with
  a second display, a presenter view: current and next slide, notes, timer
- Export PDF and .pptx; import .pptx (below)
- Undo and redo of your own edits; everyone's slide, selection and text
  cursor shown in their colour

Later (see the note): transitions, animations, tables, charts, grouping,
masters, comments.

## Inside the Yjs doc

- `meta`: `title`, `kind: 'slides'`, `version: 1`
- `deck` (Y.Map): `theme` (an id from a fixed list in code), `size`
  (`[1920, 1080]`; an imported 4:3 deck keeps `[1440, 1080]`)
- `slides` (Y.Map): slide id -> Y.Map with `pos` (fractional index
  string), `layout`, `gone` (true when deleted), `notes` (Y.XmlFragment)
  and `els` (Y.Map): element id -> Y.Map with `type` (`text`, `shape`,
  `picture`), `frame` (`{ x, y, w, h, rot }`, one plain value), `z` (a
  fractional index string), `role` (`title`, `body` or none), shape
  fields (`shape`, `fill`, `line`, `lineW`), picture fields (`ref`,
  `hash`, `mime`, `pw`, `ph`, `alt`, as the document image node) and
  `text`, a Y.XmlFragment for text boxes and shapes

Geometry is in slide space, independent of the screen. A colour is a theme
slot (`accent1`) or a hex value. Any member can write any value, so the UI
clamps what it draws (frames within -10000 to 30000, at most 1000 elements
per slide, unknown types skipped). The seeder sees only encrypted blocks.

## Order of slides and objects

Y.Array has no move. A move is delete plus insert, so two people moving the
same slide at once leave two copies of it, which then diverge.

Recommended: **fractional index keys.** The list is sorted by `pos`, then
id. A move sets `pos` to a key between the new neighbours. Two people moving
the same slide: one write wins on every device, no copy. Two slides moved
into the same gap: both stay. A tidy-up can shorten keys that grew long.
The `fractional-indexing` package (CC0, version not checked) or about 40
lines of our own, with a random suffix so two devices never make the same
key. Objects use the same method for `z`.

## Concurrent edits

- Two people move the same box: `frame` is one value, so the box ends
  where one of them put it, not with one's x and the other's y. A drag
  writes once, on release, so others see the box jump.
- Moving or relayouting a box while someone types in it: different keys,
  both kept.
- Deleting a slide someone is editing: delete sets `gone: true` and keeps
  the content, so edits made at the same time are not lost (Yjs drops edits
  into a removed map). The person on that slide sees "Ana deleted this
  slide" with Restore. A tidy-up drops gone slides. Objects are removed for
  real; undo brings them back.
- Duplicate copies the slide's maps and text with new ids; pictures keep
  the same `ref` (no new bytes).

## Rendering

Recommended: **DOM.** The slide is a 1920 x 1080 `div` scaled to fit with a
CSS transform; each element is an absolutely placed `div` rotated with CSS;
shapes are inline SVG; pictures are `img`; text boxes are TipTap editors.

- The same element shows and edits the text, so nothing jumps when
  editing starts and cursors work as in documents.
- With a canvas (Konva 10.7.1 or Fabric 7.4.0, both MIT) the canvas draws
  the text and a DOM editor laid over it edits it. The two wrap lines
  differently and canvas rich text does not bind to Yjs, so we would keep
  two text renderers in step.
- PDF export prints the same DOM, so text stays text.
- Canvas is faster with hundreds of objects; slides rarely have over 30
  (guess). Slide list thumbnails are the same DOM scaled down, as static
  HTML, drawn only when on screen.

Handles, rotation and snapping: our own code (guess 600 lines) or Moveable
(MIT, version not checked). Decide in PR 1.

## Text boxes

Only the box being edited has a live TipTap editor, bound to its `text`
fragment (`Collaboration.configure({ fragment })`); the rest render static
HTML. The schema is the document schema without headings, tables, code
blocks and images, versioned with `meta.version`. Undo is one Y.UndoManager
in the WebView over `slides` and `deck`, shared with y-prosemirror's undo
plugin so text and moves undo in one history (guess: the plugin accepts it).

## Pictures

As in documents: bytes in the writer's picture core, `ref` and `hash` in
the element. `pictures.js` and `moves.js` find references only in documents
(`docModel.images`), so each kind gets `pictureRefs` and `rewriteRef` for
tidy-ups and removals. Decks with pictures stay `version: 1`.

## Presenting

- Desktop: one display goes full screen. With two, a second Electron
  window shows the slides full screen on the other display and the main
  window becomes the presenter view; the main process keeps them on the
  same slide.
- Phones: full screen in landscape, tap either half or swipe. In portrait,
  the slide with its notes under it. A projector gets the system's mirrored
  screen (AirPlay, cast); a separate presenter screen is later.
- Edits by others during a show appear live.

## Import and export

- PDF: one page per slide through the existing `app:savePdf`.
- .pptx export with pptxgenjs 4.0.1 (MIT): text runs and paragraphs,
  shapes as preset shapes, pictures, rotation, notes, backgrounds. 1920 px
  is 13.333 in. Themes are written out as the colours and fonts they give,
  with no master (guess: enough for PowerPoint, Keynote and LibreOffice).
- .pptx import: no well-maintained JS importer gives an editable model
  (pptxtojson from PPTist, one maintainer, not checked). Recommended: our
  own reader with jszip (already a dependency) and DOMParser. It reads
  slide order and size; each shape's position, size and rotation, preset
  shape, solid fill and outline; text runs and paragraphs (formatting,
  alignment, bullets, levels); pictures; groups (flattened); notes and
  solid backgrounds. Placeholders inherit position and style from layout
  and master, which is most of the work. Lost, with a notice: animations,
  transitions, tables and charts (text kept where possible), SmartArt,
  custom shapes (drawn as their box), gradients (first colour), media, EMF
  and WMF pictures, embedded fonts.

## Presence

The state gains `slide` (an id, at most 64 characters), `sel` (up to 20
element ids) and `box` (the element `cursor` is in). The slide list shows
who is on each slide; objects others selected get an outline in their
colour. Older builds drop unknown fields (`cleanState`). The protocol stays
`pearoffice/presence/1`.

## Compat

- Older builds refuse a `f=slides` invite ("This invite needs a newer
  version of PearOffice", `LINK_KINDS`). A deck reaching one through device
  linking shows "Update PearOffice to open this file" (`App.jsx`).
- A deck with a newer `meta.version` opens read-only. Nothing is released.

## Verify

- Two engines over the local testnet: concurrent typing in one box, a
  concurrent move and resize of one box, both moving the same slide,
  both moving different slides into one gap and a delete while the other
  types. Each converges to the same state in either arrival order, with no
  duplicated slide and the typed text kept.
- An offline member catches up from the seeder alone, pictures included.
- Tidy-up of a deck with 5 pictures, 2 deleted: the new file has 3.
- .pptx: export every element type, convert with LibreOffice headless to
  PDF and check text and positions; import it back and compare; import a
  few real decks and list what was lost.
- A new desktop smoke part: add slides, type, move a box, reorder, present.
- Android emulator and iPhone Simulator: edit and present; two-device
  co-editing with the emulator and the TCL.
