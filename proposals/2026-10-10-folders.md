# Folders

**Status:** approved by Tim 2026-10-10. Tim asked for "some kind of internal file and
folder structure for organizing sheets, docs and slides".

**Goal:** a person can put their files into folders, and the same folders
show on all their linked devices and come back with the recovery phrase.

**Tier:** T2. New persisted records, two new message types on the
own-devices channel and two new sections in the keyring. No keys, crypto or
file contents change.

## What a folder is

- **Personal.** Folders are how *you* arrange your files. Putting a shared
  file in a folder changes nothing for the other people in it, and they
  never see your folder names. This is how a "Shared with me" file works in
  most office apps.
- **One level.** Folders sit on the home screen and hold files; folders do
  not hold folders. This keeps phones simple (no breadcrumbs) and avoids
  the case where two devices offline move folder A into B and B into A.
  Nesting can come later without changing the records below (a `parent`
  field).
- **A file is in one folder or none.** Files in no folder show at the top
  level, under the folders, as today.
- **Deleting a folder never deletes files.** Its files go back to the top
  level.

## Where it shows

- **Home (All files):** folders first, then the files in no folder, each
  list sorted as today. A **New folder** button sits beside New.
- **Inside a folder:** its name as the heading, its files and a back
  button; Back on Android does the same. **New** made from here puts the
  file in this folder.
- **Moving a file:** "Move to folder..." in the file's menu (the "..." on
  an open file and on a file row), a short list of folders plus "No
  folder". On desktop a file can also be dragged onto a folder.
- **Folder menu:** Rename, Delete folder.
- **The side list** (desktop, and the phone's slide-in list) shows folders
  that open and close, with their files under them.
- Joined files, files from your other devices and files restored from the
  phrase land at the top level, unless your devices already filed them.

## Records

Kept in each device's localDb, one record per id:

- `folder:<folderId>` `{ at, name }`, or `{ at, removed: true }`
- `place:<sheetId>` `{ at, folder }`, `folder` a folderId or null

`folderId` is 16 random bytes, hex. `at` is the device's clock when the
change was made. Merging keeps, per id, the record with the later `at`
(ties broken by comparing the records' bytes), the same rule the keyring
already uses. A removed folder is kept for 30 days, like keyring removals,
so a device that was offline does not bring it back.

A file whose folder is removed or unknown shows at the top level. So if one
device deletes a folder while another, offline, moves a file into it, the
file ends up at the top level on both.

Limits: 500 folders, names up to 100 characters.

## Between your devices

On the existing `pearoffice/own-devices/1` channel
(proposals/2026-10-07-own-devices-files.md), one new JSON message,
`{ t: 'folders', folders, places }`:

- after the hellos, with every record (removals included), after the
  existing `files` message, places in parts of 500;
- as soon as a folder or placement changes while the channel is open,
  with just that record.

Each side merges by the rule above and tells the UI (event
`folders:changed`).

## Backup and the recovery phrase

The keyring gains two sections, `folders` and `places`, with the same items
and merge. They are sealed with the rest, so seeders still learn nothing.
A restore from the phrase brings folders back with the files.

Placements for files the keyring no longer lists are dropped when the
keyring is written, so the list does not grow forever.

## Files that move to fresh keys

A move (removal, tidy up) gives a file a new sheetId. When a device follows
a move it copies `place:<old>` to `place:<new>` with a fresh `at`, so the
file stays in its folder. Every device follows on its own and copies the
same folder, so the copies agree.

## Compat

- **Older builds on the own-devices channel** ignore messages with an
  unknown `t`. A mixed pair shares files as today, and only the newer
  device has folders.
- **Older builds writing the keyring** drop sections they do not know
  (`keyring.js clean`). If an older device writes the keyring last, the
  seeder's copy loses the folders until a newer device writes again (once a
  minute at most, from its own localDb). A restore from the phrase in that
  window comes back without folders. Files are never affected.
- Nothing inside any file changes, so other members' versions do not
  matter.

## Verify

- Unit tests for the merge: later wins, ties, removals, a file in a removed
  folder showing at the top level, the 30-day drop, limits.
- Engines over the test DHT: two linked devices; a folder made and a file
  moved on one shows on the other within seconds; both offline, one renames
  a folder and the other deletes it, and they agree after reconnecting; a
  file that moves to fresh keys stays in its folder; a restore from the
  phrase brings folders back; an older keyring without the sections opens.
- Desktop smoke part `folders`: New folder, Move to folder, drag onto a
  folder, New inside a folder, rename, delete (files come back to the top
  level) and reopening.
- Android emulator: folders on the home screen, opening one, Back, Move to
  folder.

## Rollback

Hide folders in the UI. The records stay unused in localDb and the
keyring; every file still shows at the top level. Nothing else depends on
them.

## Decided 2026-10-10

1. One level first.
2. Personal folders only. Shared folders are not planned.
3. Joined files land at the top level.
