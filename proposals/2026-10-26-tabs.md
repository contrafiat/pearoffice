# Open files in tabs (desktop)

**Status:** approved by Tim 2026-10-26: tabs stay loaded, come back after a restart, desktop only. The tester who asked for windows also said "I'm used to
working in tabs and multiple screens" (tester feedback 2026-10-26). Windows
shipped in PR #258 (proposals/2026-10-26-file-windows.md); this adds tabs
in a window.

**Goal:** on desktop, several files can be open at once in the main window,
one tab each, and you switch between them without going back to the file
list.

**Tier:** T1. The UI and the desktop shell only. No change to the worklet,
the files or the wire format.

## How it looks

- A row of tabs above the open file: each with the file's kind icon, its
  title and a close button. The tab of the file on screen is highlighted.
- Opening a file (a card, the side list, a link, an @ chip, New, Import,
  a join) opens it in a new tab, or switches to its tab if it has one.
- All files and the folders stay in the side list and are not tabs. Going
  to All files keeps the tabs; clicking one comes back to that file.
- With one tab or none, the row is hidden, so the app looks as it does now
  until a second file is open.

## Keys and mouse

- Ctrl+Tab and Ctrl+Shift+Tab: next and previous tab. Ctrl+1 to Ctrl+9:
  that tab (9: the last). Ctrl+W: close the tab. Cmd on a Mac.
- Middle click on a tab closes it. Drag tabs to reorder them.
- A tab's right-click menu: Close, Close other tabs, Open in new window.
- Dragging a tab out of the window opens it in its own window (the windows
  from PR #258), and the tab closes.

## The rules

- A file is in one place: a tab or its own window. Opening a file that has
  a window brings the window forward, as now. Open in new window closes
  its tab.
- A file that moves to fresh keys keeps its tab. A file that is removed,
  deleted or left closes its tab.
- At most 20 tabs; opening a 21st closes the one used longest ago.

## Open questions

1. **Keep the tabs not on screen loaded, or load a tab when you switch to
   it?** Kept loaded: switching is instant and keeps undo, scroll position
   and the selected cell; each open tab uses memory and counts you as
   "in" that file for the others (the presence dots). Loaded on switch:
   lighter, but switching takes a moment and undo and scroll start fresh.
   Proposed: keep them loaded, and show you in a file only while its tab
   is on screen.
2. **Reopen the tabs after a restart?** Proposed: yes, like windows, kept
   on this device (per device, in the page's storage).
3. **Phones and tablets?** Proposed: not now. Phones have no room for a tab
   row.

## Verify

- Smoke (a new `tabs` part): open three files, switch by click and by
  Ctrl+Tab and Ctrl+2, edit in one and switch back with its undo and
  selected cell kept, close with Ctrl+W and a middle click, All files and
  back, Open in new window from a tab, a removed file's tab closing, the
  tabs back after a reload.
- `npm run verify`.
- By hand on Linux with the dev copy (`npm run desktop`).

## Rollback

Revert. The saved tab list is left in the page's storage and ignored.
