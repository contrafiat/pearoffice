# Tags and search for files

**Status:** draft, waiting for Tim. From the tester (MLI), 2026-10-28:
"Folder inside of folder doesn't work but then I have an idea that it is
probably even better with a tagging system on top of the folders. For
example: Bicycle, sports, economy budget ... and then a search function with
one or multiple tags." Tim chose tags and search, with folders staying one
level, and picking several tags shows files that have all of them.

**Goal:** a person can give their files tags, find files by name and tags
from the file list, and see the same tags on all their linked devices and
after a restore from the phrase.

**Tier:** T2. New persisted records, one new message type on the
own-devices channel and two new sections in the keyring, the same shape as
folders (proposals/2026-10-10-folders.md). No keys, crypto or file contents
change.

## What a tag is

- **Personal**, like folders. Tagging a shared file changes nothing for the
  other people in it, and they never see your tag names.
- **Many per file.** A file can have any of your tags (up to 20), and is
  still in one folder or none.
- **Deleting a tag never touches files.** It comes off every file.

Folders stay one level (proposals/2026-10-10-folders.md, decided
2026-10-10). Tags cover the "this file belongs in two places" need that
nesting would otherwise be asked for.

## Where it shows

- **Tagging a file:** "Tags..." in the file's menu (the "..." on an open
  file and on a file row). A short list of your tags with ticks, and a box
  to type a new one. On desktop the same list opens from the file's tags on
  its row.
- **On a file row:** its tags as small grey pills after the name, up to
  three, then "+2".
- **Search on the file list:** a search box above the files. It matches
  file names as you type. Below it, your tags as pills to tap; picked tags
  show files that have **all** of them. Name and tags combine. Clear (x)
  resets both.
  - At home (All files), search covers every file, including those inside
    folders; each result shows its folder's name.
  - Inside a folder, search covers that folder only.
  - With no tags yet, only the name box shows.
- **Managing tags:** "Manage tags" at the bottom of the Tags... list:
  rename and delete.
- Phones: the tag pills scroll sideways in one row, as the toolbars do.

Tags have no colours in this version (see Open questions).

## Records

Kept in each device's localDb:

- `tag:<tagId>` `{ at, name }`, or `{ at, removed: true }`
- `tagged:<sheetId>:<tagId>` `{ at, on }`, `on` true or false

`tagId` is 16 random bytes, hex. One record per file and tag, so two
devices adding different tags to the same file while offline both keep
their tag. Merging is the folders rule: per key, the later `at` wins, ties
broken by comparing the records' bytes. Removed tags and `on: false`
records are kept for 30 days, then dropped.

A `tagged` record pointing at a removed or unknown tag is ignored. Names are
unique ignoring case: making "budget" when "Budget" exists picks the
existing one. If two devices offline both make "Budget", the list shows
one and the file list treats both ids as that tag; the next time either is
used, the device tags with the older id.

Limits: 200 tags, names up to 40 characters, 20 tags per file.

## Between your devices

On `pearoffice/own-devices/1`, one new JSON message
`{ t: 'tags', tags, tagged }`, sent like `folders`: everything after the
hellos (in parts of 500), then each change as it happens. Event
`tags:changed` tells the UI.

## Backup and the recovery phrase

The keyring gains `tags` and `tagged`, with the same merge, sealed with the
rest. `tagged` records for files the keyring no longer lists are dropped
when it is written.

## Files that move to fresh keys

When a device follows a move it copies each `tagged:<old>:*` to
`tagged:<new>:*` with a fresh `at`, as it does for its folder.

## Compat

As for folders: older builds ignore the unknown message and drop the
unknown keyring sections. If an older device writes the keyring last, the
seeder's copy lacks tags until a newer device writes again (once a minute
at most). Files are never affected.

## Verify

- Unit tests: merge order, ties, offline adds of different tags to one file
  both kept, removals and the 30-day drop, a tagged record for a removed
  tag ignored, same-name tags, limits, the search filter (name, one tag, two
  tags, both, inside a folder).
- Engines over the test DHT: two linked devices; a tag made and added on one
  shows on the other; both offline, each adds a different tag to the same
  file and both stay; a moved file keeps its tags; a restore brings tags
  back; an older keyring opens.
- Desktop smoke part `tags`: Tags... from a row and an open file, a new tag,
  pills on the row, search by name, by one tag, by two (all of them), a
  search inside a folder, rename and delete from Manage tags, reopening.
- Android emulator: Tags..., the pills row scrolling, search.

## Rollback

Hide tags and the tag pills in the UI. The records stay unused. Name search
does not depend on them and can stay.

## Order

1. Name search on the file list (no new records; useful on its own).
2. Records, merge and IPC (`file:tags`, `file:newTag`, `file:renameTag`,
   `file:deleteTag`, `file:tag`), with unit tests.
3. Tags..., pills on rows, tag filter, Manage tags.
4. The own-devices message, keyring sections and moves, with engine tests.

## Open questions

1. Colours for tags: none (as above), or a colour from a fixed set picked
   automatically, or chosen by the person?
2. Should search also look inside files (the text of documents and cells)?
   Recommended: no, names and tags only for now. Searching contents means
   opening every file, which is slow on a phone with many files.
