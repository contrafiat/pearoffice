# Charts

**Status:** approved by Tim 2026-10-04: ECharts, Excel charts written in
this work, charts float over the grid. From section 4 of
`notes/2026-10-04-calc-parity.md`.

**Goal:** charts drawn from a sheet's cells that update as the cells change,
shared with everyone in the sheet: column, bar, line, area, pie, doughnut,
scatter and combined column-and-line to start, with titles, legend, data
labels and axis settings.

**Tier:** T2. Each tab gains a new shared map of charts. Older builds ignore
it: they keep working and show no charts.

## What a chart is

A chart is a small description stored in the tab, never a picture. Every
device draws it from the current cell values, so it follows edits, spills
and `A2#`.

Each tab map gets a `charts` Y.Map: chart id → a Y.Map with one key per
setting, so two people changing different settings of one chart both keep
their change (as with cell formats).

| Key | Value |
| --- | --- |
| `type` | `column`, `bar`, `line`, `area`, `pie`, `doughnut`, `scatter`, `combo` |
| `data` | the data range, stored like a formula reference (cell ids, so it follows inserted and deleted rows; `A2#` allowed) |
| `seriesIn` | `columns` or `rows` |
| `labels` | the first row and/or column holds names (`{ row, col }`) |
| `title`, `xTitle`, `yTitle` | text |
| `legend` | `right`, `bottom`, `none` |
| `dataLabels`, `stacked`, `percent` | booleans |
| `yMin`, `yMax`, `yFormat`, `logScale` | axis settings |
| `lineSeries`, `secondAxis` | for `combo`: which series are lines, and which use a right-hand axis |
| `trendline` | series indexes with a straight-line trend and its R² |
| `anchor` | `{ row, col }` cell ids of the top-left corner, plus `dx`, `dy` offset in pixels |
| `size` | `{ w, h }` in pixels |

A data range whose rows or columns were all deleted shows "The data for this
chart was deleted" in place of the chart. Deleting the chart removes its key.

**Who can change charts:** owners and editors, like cells (chart changes
travel in the same `y` updates, which only writers can append). Viewers see
them.

## Drawing

- **Library: ECharts** (Apache-2.0), with only the chart types and parts
  used, drawn as SVG. About 620 KB minified (210 KB compressed) added to the
  app, which is about 750 KB today. It has every type above plus radar,
  bubble, candlestick, funnel and heatmap for later, data labels, two axes
  and image export built in. Chart.js (MIT, about 200 KB) was the
  alternative: smaller, but needs add-ons for data labels and has no SVG
  export.
- Charts are drawn on each device; nothing about the drawing is shared, so
  drawing differences between devices do not matter.
- Colours come from the app's palette in light and dark mode, so a chart
  reads well in both.

## Placing and editing

- **Insert:** select data, then "Insert chart" (toolbar on desktop, More
  menu on phones). PearSheet guesses the type, series direction and labels
  from the selection, as Calc and Excel do, and opens the chart editor.
- **On desktop** a chart floats over the grid, anchored to a cell, so it
  moves with inserted rows and columns. Drag to move, drag a corner to
  resize; the chart menu has Edit, Download PNG, Download SVG and Delete.
- **On phones** a chart shows at its place in the grid at the grid's zoom;
  tapping it opens it full screen with the same menu.
- **Chart editor:** type, data range (typed or "use selection"), series in
  rows or columns, labels, titles, legend, data labels, stacking, axis
  minimum, maximum, number format and log scale, combo settings, trend
  lines. Changes show live.

## Files

- **.xlsx export:** SheetJS Community Edition does not write charts, so
  PearSheet adds them itself: after SheetJS writes the workbook, the export
  adds a DrawingML chart part per chart, a drawing part per tab that places
  them at their anchor cells, the relationships and the content types. The
  chart's data range goes in as cell references with the current values
  cached, so Excel and LibreOffice draw it at once and redraw it from the
  cells.
- **.xlsx import:** SheetJS Community Edition does not read charts either, so
  charts in imported files are not brought in; the import says so.
- **PNG and SVG:** from the chart menu.
- **PDF and print:** a tab's charts are drawn below its table.

## Compat

Older builds ignore the `charts` map and show no charts; the data is
unaffected. A chart edited only by older builds cannot happen, since they
cannot see it.

## Verify

- `npm run verify` green.
- Unit: chart settings merge per key between two devices; a data range
  follows inserted and deleted rows; a deleted range is reported; the
  guess of type, series direction and labels for common selections.
- Desktop smoke: insert a chart from a selection, change a cell and see the
  chart's data change, change the type, download a PNG, delete the chart.
- Emulator and Simulator: a chart in the grid, full screen on tap, in dark
  mode.

## Rollback

Revert. The `charts` maps stay in documents unused.

## Decided

1. ECharts.
2. Excel charts are written into .xlsx exports in this work (built in two
   steps: charts in the app first, then the file export).
3. Charts float over the grid.
